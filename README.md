# De Paul School application

The repository is organized into two applications:

- `frontend/` — Next.js visitor website and administrator interface.
- `backend/` — Express API backed by Supabase Postgres and Storage.

Run the frontend with `npm run frontend:dev` and the backend with `npm run backend:dev`. Configure each application's environment file separately. The Next.js API routes remain under `frontend/src/app/api` only during the staged migration; new and migrated API code belongs in `backend/src`.

Apply `backend/supabase/migrations/002_site_images.sql` to enable the Website Images section, `backend/supabase/migrations/004_exam_result_workbook_metadata.sql` to retain exam serial numbers and dates, `backend/supabase/migrations/005_exam_result_import_history.sql` before publishing workbook imports, and `backend/supabase/migrations/006_campus_facilities.sql` to enable admin-managed campus facilities. The Facilities admin section supports creating, editing, ordering, publishing, and deleting facility cards; photos are optional and can be added later from Gallery Management. The exam-results preview accepts multi-sheet `.xlsx` and compatible `.xls` workbooks, reads saved formula results without recalculating them, and keeps each detected class separate. It supports both subject/max/obtained header groups and marksheets with subjects across columns and a separate maximum-marks row. When a roll number is absent, the serial number is retained and used as the result lookup identifier. Rows with blocking validation issues remain visible in preview and are excluded; valid rows in eligible selected classes can still be published. Selected-class publishing is transactional and records workbook history, status, counts, and validation failures in Supabase. The student portal displays the stored result values without rounding or recalculation. Admin image uploads are optimized and stored in the public `site-images` bucket; gallery photos, event images, and staff photos continue to be managed in their existing admin sections. Supabase migrations and database maintenance scripts live under `backend/`.
